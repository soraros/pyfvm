# Reference study: pinned pyfvm

This study uses public pyfvm commit
[`cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac`](https://github.com/soraros/pyfvm/tree/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac),
the requested `main` reference, rather than the repository's default `master`.
The complete repository tree and relevant source files were inspected.

## Mathematical authoring

The [form language](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/src/pyfvm/form_language.py)
represents a residual as a sum of integrals returned by `apply(self, u)`.
An integrand is a Python callable evaluated with symbolic coordinates; `u` is a
SymPy function. `n_dot_grad` and `n_dot` are symbolic operator markers. The three
measures are `dS` for control-volume surfaces, `dV` for control-volume interiors,
and `dGamma` for external cell surfaces. Dirichlet conditions are authored as
residual expressions with subdomain selectors.

The [README examples](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/README.md)
demonstrate Poisson and Bratu equations in this language. This is genuine
mathematical authoring followed by local discretisation and code generation.

## Local discretisation and generated derivatives

In [discretize_linear.py](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/src/pyfvm/discretize_linear.py),
`DiscretizeEdgeIntegral` replaces the normal derivative along an edge by the
endpoint difference divided by edge length. It multiplies the result by
`edge_ce_ratio * edge_length`, using geometry supplied by the mesh. Ordinary
field values and spatial coefficients are evaluated at edge midpoints.

Thus a pure diffusion term on edge `(i, j)` contributes
`c * (u_i - u_j)`, with local matrix `c * [[1, -1], [-1, 1]]`.
The second residual entry is generated by exchanging endpoints and coordinates.
Volume terms use vertex evaluation multiplied by the vertex control volume.
The linear external-face path uses nodal evaluations and face partitions.

The nonlinear path in [discretize.py](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/src/pyfvm/discretize.py)
first creates the discrete local expression, then differentiates it with
`sympy.diff`. Values and local derivatives become numerical callables through
`sympy.lambdify` targeting NumPy. These are generated numerical functions;
they are not machine-code kernels. The linear path extracts affine and linear
coefficients and rejects a nonzero nonlinear remainder.

## Native representation and assembly

The standard implementation uses one unknown per mesh vertex. The
[Jacobian](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/src/pyfvm/jacobian.py)
builds local edge blocks and diagonal vertex contributions, then constructs COO
and converts to CSR. The [residual assembler](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/src/pyfvm/fvm_problem.py)
uses `npx.add_at`. Dirichlet conditions replace rows. The
[linear assembler](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/src/pyfvm/linear_fvm_problem.py)
also reduces diagonal and right-hand-side contributions before sparse assembly.

Complex-valued examples retain the vertex layout; they do not introduce an
independent cell or trace representation. In particular, the
[Ginzburg–Landau example](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/examples/ginzburg_landau_example_test.py)
supplies its nonlinear residual and Jacobian action manually.

## Arithmetic and implementation limits

Expression simplification, expansion and SymPy canonicalisation can change
evaluation order. Kernel collections are sets. Local outputs are rounded arrays,
and incidence and sparse duplicates use ordinary reduction. No compensation
contract connects symbolic authoring, local derivatives and global assembly.
An accurate final sum cannot recover a component discarded in a local subtotal.

Some general-looking interfaces are incomplete in the pinned source. Nonlinear
`dGamma` construction omits the required `FaceKernel` subdomain argument, and
its later use expects a plural attribute absent from that class. Edge and vertex
kernel constructors hardcode their subdomains. The
[Neumann tests](https://github.com/soraros/pyfvm/blob/cbf9d2bf2bdcfc2b6cc37ad46ed66b986cd8efac/tests/test_neumann.py)
are explicitly skipped because the required mesh face partitions are unavailable.
These are source-inspection findings, not results from running the full suite.

## Executed form-composition control

The exact pinned AST definitions of `Measure`, `ControlVolume`,
`ControlVolumeSurface`, `CellSurface`, `Integral`, `IntegralSum` and `integrate`
were compiled and exercised without importing the mesh or SymPy runtime.
The integrands were constant Python callables. Their `repr` methods were unused.
This executed the original composition classes, not a rewritten approximation.

For a two-integral sum with integrands `2` and `3`, the results were:

| Operation | Expected integrands | Actual integrands |
| --- | --- | --- |
| `1 - (2 + 3)` | `[1, -2, -3]` | `[1, -3, -3]` |
| `-(2 + 3)` | `[-2, -3]` | `[-3, -3]` |
| `2 * (2 + 3)` | `[4, 6]` | `[6, 6]` |

The lambdas created by `IntegralSum.__sub__`, `__neg__` and `__mul__` share the
comprehension's final `integral` binding. Addition also mutates its left operand:
after `b = a + other`, `a is b` is true and `a` contains both integrals.
These findings motivate immutable ordered authoring objects. They do not imply
that every existing example fails: subtraction of a single integral avoids the
multiple-integral late-binding case. No full upstream runtime test is claimed.

## Influence, separation and attribution

The useful conceptual sequence is mathematical authoring, explicit local
discretisation, generated discrete derivatives, and assembly through incidence.
The new experiment adopts that sequence while making representation and
arithmetic contracts explicit. Its implementation is independently written:
it neither imports pyfvm nor adapts its numerical implementation. It is confined
to `experiments/absim_neo`; the original upstream source remains intact.
